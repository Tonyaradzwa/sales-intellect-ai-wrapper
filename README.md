# sales-intellect-ai-wrapper

This is an unofficial Python wrapper around the [Sales Intellect POS API](https://developer.salesintellectpos.com/). It lets you create and update products and inventory using natural language input, which a Claude agent processes in the background.

## Setup

```bash
pip install requests
export SI_API_TOKEN=your_token_here
```

## Usage

```python
from client import SalesIntellectClient

client = SalesIntellectClient()  # reads SI_API_TOKEN from env, or pass token=...

# List products
products = client.list_products()

# Create or update a product
client.upsert_product({"name": "Widget", "sku": "WID-1", "price": 9.99})

# List shops
shops = client.list_shops()

# Check inventory for a shop
inventory = client.get_inventory(shop_id="123")

# Set stock to an absolute value
client.set_inventory(shop_id="123", product_id="456", in_stock=42)

# Adjust stock by a relative amount (reads current level, then writes new total)
client.adjust_inventory(shop_id="123", product_id="456", delta=5)
```

See [example.py](example.py) for a runnable script covering: list products,
check inventory, adjust stock by +5.

## Web UI

The Streamlit UI ([app.py](app.py)) is a paste-and-parse tool for turning raw
WhatsApp text into Sales Intellect writes, with two tabs:

- **Product Updates** — for stock received against existing products. Every
  item here is a stock update matched against the current catalog (fuzzy
  matching, and a single phrase like "all pink leotards" can expand into one
  update per matching product); anything the fuzzy match can't confidently
  place is flagged rather than guessed or silently dropped. Includes a shop
  dropdown, since `adjust_inventory()` needs a `shop_id`.
- **Bulk Product Upload** — for adding brand new products (e.g. "add new
  product: Kickboards Large, price 8.50"). No shop selector, since these are
  plain `upsert_product()` calls.

Both tabs work the same way: paste raw text into the chat box (as many times
as you like — each paste appends more rows) -> review/edit each line item in
the table below, deleting any that don't belong -> "Confirm and Submit".
Nothing is written to Sales Intellect until that final confirm step. Chat is
paste-only; corrections happen directly in the table (every field is
editable, and each row has a delete button).

The product catalog is always fetched fresh — no caching — so matching and
code numbering are always against the current state of Sales Intellect. New
product names are always Title Cased with "w/" spelled out as "With", and new
product codes are generated by incrementing the highest existing numeric code;
this is re-checked (and regenerated if it's been taken by something added in
the meantime) right before the write happens.

1. **Backend** ([server.py](server.py)) — a Flask app with two endpoints:
   - `POST /parse`: takes raw pasted text and a `mode` (`"product_updates"` or
     `"new_products"`). Runs a small [Claude Agent SDK](https://docs.claude.com/en/api/agent-sdk/overview)
     agent, scoped to that one task (the tab already tells it whether it's
     doing stock updates or new products, so it never has to classify that
     itself), with three tools:
     - `search_products(query)` — fuzzy/substring search over the current
       catalog, returning the top ~10 candidate matches (id + name). This is
       what keeps the whole catalog (which can be thousands of products) out
       of the prompt — the agent only ever sees the handful of candidates
       relevant to what it's currently looking up.
     - `generate_next_product_code()` — new-product tab only; a plain local
       function (no LLM reasoning over the catalog) that finds the highest
       existing numeric product code and returns the next one.
     - `submit_result(...)` — the agent calls this once per line item it
       finds in the pasted text (or once per product, when a phrase like "all
       pink leotards" refers to a whole group), with the schema the
       confirmation UI expects: `matched_product_id` + `quantity` for stock
       updates, or `suggested_name` + `suggested_product_code` + `fields` for
       new products. Genuinely unmatched items are still submitted (with
       `matched_product_id: null`) rather than skipped or guessed at, so
       staff can be told what wasn't found.

     The agent's tool-call loop is handled entirely by the SDK's `query()` —
     there's no hand-rolled "check stop_reason, run the tool, append the
     result, call again" loop here.
   - `POST /confirm`: takes the (possibly staff-edited) items plus an optional
     `shop_id` (required only if any item is a stock update), and calls
     `upsert_product()` / `adjust_inventory()` for each one sequentially.
     Returns a per-item success/failure result.

   Nothing is written to Sales Intellect during `/parse` — only `/confirm`
   performs writes, and only after staff review.

2. **Frontend** — each tab in [app.py](app.py) is a chat box backed by
   `/parse`, with an editable review table below it (fix names/quantities/
   codes, pick from close-match candidates, delete a row) and a "Confirm and
   Submit" button.

Run both with one command:

```bash
pip install flask claude-agent-sdk
npm install -g @anthropic-ai/claude-code   # gives the SDK the `claude` CLI it drives
export SI_API_TOKEN=your_si_token
export ANTHROPIC_API_KEY=your_anthropic_key
./run.sh
```

This starts the Flask backend (`http://localhost:5050`) in the background and
the Streamlit UI (`http://localhost:8501`) in the foreground; Ctrl+C stops
both. If the backend runs somewhere other than `localhost:5050`, set
`SI_BACKEND_URL` before running.

Note: port 5000 is avoided because on macOS it's usually occupied by Control
Center's AirPlay Receiver, which silently swallows requests meant for your
backend.

Note: the first time the `claude` CLI runs on a machine it may prompt
interactively (folder trust, terms) before it will run headlessly for the
SDK. If `/parse` fails on a fresh machine, run `claude` once by hand in this
directory to get past that, then restart the backend.

## Deployment

Runs on a small EC2 instance behind a [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) with [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/policies/access/) doing login. Cloudflare terminates HTTPS and authenticates staff before traffic ever reaches the box — the app itself only listens on `127.0.0.1` and has no public inbound port.

### 1. Launch the EC2 instance

- Ubuntu 24.04 LTS, `t4g.small`/`t3.small` (arm64 or amd64 both work) or larger.
- Security group: allow inbound SSH (22) **from your IP only**. No other inbound ports — the tunnel makes an outbound connection from the instance to Cloudflare, so nothing needs to be opened for web traffic.

### 2. Clone the repo and configure secrets

```bash
ssh ubuntu@<instance-ip>
git clone <this-repo-url> /home/ubuntu/app
cd /home/ubuntu/app
cp .env.example .env
nano .env   # fill in SI_API_TOKEN and ANTHROPIC_API_KEY at minimum
```

### 3. Run setup

```bash
./deploy/setup.sh
```

This installs Python/venv, Node.js 22 + the Claude CLI, adds a 2GB swap file if RAM is under 2GB, creates the venv, installs `requirements.txt`, and installs + enables both systemd services (`sales-intellect-flask`, `sales-intellect-streamlit`). It's safe to re-run. If `.env` wasn't filled in yet, fill it in and run:

```bash
sudo systemctl restart sales-intellect-flask sales-intellect-streamlit
```

### 4. Cloudflare Tunnel

```bash
cloudflared tunnel login
cloudflared tunnel create sales-intellect-ai-wrapper
cloudflared tunnel route dns sales-intellect-ai-wrapper app.<yourdomain>
```

In the tunnel's config (`~/.cloudflared/config.yml`), point the hostname at the Streamlit port:

```yaml
tunnel: <tunnel-id>
credentials-file: /home/ubuntu/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: app.<yourdomain>
    service: http://localhost:8501
  - service: http_status:404
```

Then install it as a service so it survives reboots:

```bash
sudo cloudflared service install
```

### 5. Cloudflare Access

In the Cloudflare dashboard, add an Access application for `app.<yourdomain>` and a policy allowing your staff's email addresses (or your workspace's email domain). Staff will be prompted to authenticate before Cloudflare ever forwards a request to the tunnel.

### 6. Deploying updates

```bash
cd /home/ubuntu/app
./deploy/update.sh
```

Pulls the latest code, reinstalls `requirements.txt` only if it changed, and restarts both services.

## Notes

- No retries or pagination handling — this is intentionally bare-bones.
- Non-2xx responses raise a plain `Exception` containing the response body.
- Rate limit is 300 requests / 300 seconds; this client does not throttle
  requests for you, so pace calls accordingly if doing bulk operations.
- Product Updates only ever adjusts stock quantities (`adjust_inventory`) —
  it does not change price/cost on an existing product. Doing that safely
  would mean fetching the full existing product record and re-posting it
  with only the price changed (since it's unclear whether `upsert_product`
  does a partial or full-replace update, blindly posting a two-field payload
  risks wiping the rest of that product's fields). Ask if you want this
  wired up.
